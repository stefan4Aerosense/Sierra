AeroNode™ v1 — Build & Bring-Up Plan
Parallel tracks: software on OTS hardware + PCB in parallel
Field
Detail
Owner
Duran de Villiers — Aerosense Engineering
Date
25 June 2026
Status
Draft plan — for team alignment (Peter + Black Box)
Objective
Maximum velocity to a flying, data-generating prototype while de-risking the custom board in parallel
Operating principle
Decouple software cadence from hardware cadence. Peter develops the full stack on off-the-shelf (OTS) hardware starting now, with zero dependency on the PCB. Black Box runs the hardware track in parallel so we start hitting board-level snags early. The two tracks converge once the software is mature and the board is bring-up-ready. Neither track waits on the other.
Why this is the fast path: a flying OTS testbed gives us real DSMA™ and synthetic-airspeed data and demo material immediately, while the custom board absorbs its inevitable first-spin iterations off the demo critical path.
Track A — Software & flight testbed (OTS) · Peter, starts now
Hardware-identical to the v1 design where it matters (STM32H7 + ADIS16470 + multi-IMU + heater + Pi). Use a CUAV X7+ Pro (or Pixhawk 6X) + Raspberry Pi 5 + u-blox M10 GPS.

Track B — Hardware / PCB (Black Box) · starts now, in parallel
Two sub-steps run together. B1 de-risks the one subsystem a respin can’t cheaply fix; B2 starts the full board immediately so we surface integration bugs early — speed-first.
B1 — IMU-cluster carrier daughterboard (fast spin)
Just the 3-IMU cluster + heated island + foam cover on a small carrier.
Validates: heated-island thermal hold, ADIS16470 BGA assembly/yield, bias stability, vibration response.
Gate output: freeze the IMU-cluster layout once it passes — this block then drops into the full board verbatim.
B2 — Full v1 PCB (EVT Rev A) — in parallel
Schematic + layout: STM32H7, 3-IMU cluster, heater + MOSFET drive, per-IMU LDOs, separate SPI buses, Pi interface, M10 GPS, connectors.
Order long-lead parts now (ADIS16470 — multi-week lead).
Treat explicitly as a first-spin prototype expecting 2–3 revisions; the goal is to find snags, not to be right first time.
